# For evaluators

No public status is recorded for this series. A version number in a report's front matter is that report's version. It is not a status label for the software the report describes.

## What a published report is

The catalogue in [publications-index/catalog.yaml](../publications-index/catalog.yaml) is the list. `status: published` means a GitHub release and a DOI, as [the index](../publications-index/README.md) defines those words.

| Report | Version in the catalogue | Website page |
|--------|--------------------------|--------------|
| SF-TR-2026-001 | 1.0.3 | [https://synapticfour.com/en/publications/sf-tr-2026-001/](https://synapticfour.com/en/publications/sf-tr-2026-001/) |
| SF-TR-2026-002 | 1.0.0 | [https://synapticfour.com/en/publications/sf-tr-2026-002/](https://synapticfour.com/en/publications/sf-tr-2026-002/) |

German and French pages use the same path under `/de/` and `/fr/`.

The publication strategy says the source-code repository is authoritative for behaviour, and that a website page is the discovery layer. The report is the citable archive of the design write-up.

## What a published report is not

- The internal technical and editorial review in [workflow.md](workflow.md) is not a journal peer review. [journal-conference-roadmap.md](journal-conference-roadmap.md) says an SF-TR is usually acceptable as a non-peer-reviewed preprint when a venue asks about prior publication.
- SF-TR-2026-001 states that a HelixTest result is a technical conformance signal, not official GA4GH certification. This series does not add a certificate on top of that sentence.
- Candidate topics in [future-reports.md](future-reports.md) are not a schedule, and they are not published reports.
- Copying the template onto `reports/SF-TR-2026-001` or `reports/SF-TR-2026-002` replaces a published source. [Getting started](GETTING-STARTED.md) says how to render without doing that.
